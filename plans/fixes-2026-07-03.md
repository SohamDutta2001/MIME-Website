### What changes
The current events section (a single auto-scrolling Embla carousel) is replaced by a new top-level section with four named sub-panels arranged vertically on the homepage. The `id="events"` anchor stays in place so the nav link still works.

| c | The Third Space | Static copy about black box venue rental | Hardcoded JSX |
| d | Our Roots | Static intro copy + expandable programme cards (accordion, click to expand) | Second tab in Google Sheets |

Do **not** add new components inside `CafeApp.jsx`. Extract everything into the existing `src/components/islands/events/` directory:

```

    OurRoots.jsx            ← segment (d): static intro + ProgrammeAccordion
```

In `CafeApp.jsx`, replace `<EventsCarousel />` with `<EventsSection />` (single import swap).

### Section details

**Section (a) — CafeEvents:**
- `CafeEvents.jsx` renders: section heading → `<EventsCarousel />` → small static "collaborate" strip below (handwritten-style CTA + cafe contact email).
- `EventsCarousel.jsx` stays exactly as it is — a carousel component, nothing more.

**Sections (b) and (c) — FirstStage / ThirdSpace:**
- Hardcoded JSX with the supplied copy. No Sheet dependency.
- First Stage contact: email + "walk-ins welcome" note.
- Third Space: venue rental copy.

**Section (d) — OurRoots:**
- Static intro paragraphs from the supplied copy.
- Below the intro: `<ProgrammeAccordion />` — an independent accordion component (not EventCard logic, which contains routing). Each row shows title + short description; clicking expands to full details.
- `ProgrammeAccordion` receives an array of programme entries as props (sourced from Sheets at build time).

**Data pipeline:**
- Follow the same data-loading strategy already used for the menu and events (build-time fetch → JSON written to `src/data/`).
- Extend the existing `scripts/sync-menu.mjs` to support multiple Sheet tabs in a **generic** way, so additional tabs can be added in future with minimal changes (e.g. a `tabs` config array rather than hardcoded tab names).
- The Our Roots tab output lands in `src/data/instituteData.json`, imported by `OurRoots.jsx`.

### Responsive behaviour
All four panels must stack naturally on mobile with consistent vertical spacing. The events carousel must remain swipeable on touch devices (it already is — don't regress this). No new horizontal scroll is introduced.

### Animation & visual consistency
- Reuse existing Framer Motion `fadeUp` reveal animations and `whileInView` entrance patterns for each new panel. New sections should feel like a natural extension of the page, not static inserts.
- All new sections must follow the site's existing design language: torn-paper edges where appropriate, handwritten (`font-hand`) accents, vintage serif typography, warm colour palette (`tea`, `cream`, `maroon`, `moss`, `amber`), generous whitespace, and cinematic pacing. Do not introduce UI styles that feel materially different from the rest of the experience.

## Fix 4 — Fixed Header Text: Always Readable

### What changes
The `Nav()` component in `CafeApp.jsx` is fixed at the top of the page and has two states: an overlay state (over the hero, dark gradient background, cream text) and a scrolled state (cream background, dark text). Two issues reduce readability:

1. **Gradient too transparent at bottom** — `to-[#1C1208]/30` allows up to 70% of the hero image to bleed through, washing out the cream title and amber subtitle on lighter image regions.
2. **Mid-scroll transition zone** — at `scrollY ≈ 60px` the 500ms cross-fade leaves both background and text in intermediate states where contrast is at its lowest.

### Approach
**Step 1 — gradient opacity (required):**
Increase the gradient stops on the overlay state:

```
// before
from-[#1C1208]/95 via-[#1C1208]/75 to-[#1C1208]/30

// after
from-[#1C1208]/95 via-[#1C1208]/80 to-[#1C1208]/65
```

**Step 2 — backdrop blur (conditional):**
If the gradient fix alone produces readable text across all hero image variants, stop there. Only add `backdrop-blur-sm` to the overlay state if testing reveals that the gradient increase is still insufficient — blur alters the aesthetic and should be the last resort, not the default.

No typography, colour, spacing, animation, or routing changes.

| File | Change |
|---|---|
| `src/components/islands/CafeApp.jsx` | One line in `Nav()` — gradient stop values; blur only if required after testing |
